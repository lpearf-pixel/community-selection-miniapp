# 春华秋实品牌首页与自动点击薄框架设计

**状态：** 用户已确认视觉方向与轻量模块化约束，可进入实现计划  
**基线：** `stable/l48-business-base@7d7622342f2669e7bb69d9a4996189f5f351c440`  
**功能分支：** `codex/l49-brand-home-e2e`

## 1. 目标

第一阶段把微信小程序从通用蓝色原型升级为“春华秋实”品牌首页，建立可小幅调整、可替换视觉模板的轻量模块化页面框架，并建立不依赖页面位置、样式类名或按钮文案的自动点击薄框架。

正式品牌名为“春华秋实”，副标题为“社区甄选”，品牌口号固定为：

> 健康源于自然，温暖来自邻里

本阶段只完成全局品牌基础、首页和首页点击冒烟测试。商品、团购、购物车、订单、售后、个人中心的完整换肤留在后续独立阶段，每完成一条业务链路再补对应点击测试；视觉截图基线在主要页面稳定后建立。

## 2. 品牌与视觉规范

视觉方向采用已确认的“浅色精品有机 + 清新田园”融合方案：保留精品有机版式的层级与秩序，使用暖米白、鼠尾草绿和嫩叶绿提亮页面，丰收金仅作少量强调。

### 2.1 设计色板

| 用途 | 色值 | 说明 |
|---|---:|---|
| 品牌深绿 | `#315B45` | 标题、主按钮、选中状态 |
| 鼠尾草绿 | `#8FAF98` | 次级背景、标签、装饰 |
| 嫩叶绿 | `#68A85B` | 新鲜、在售、进度状态 |
| 暖米白 | `#FAF7EE` | 页面主背景 |
| 卡片白 | `#FFFDF8` | 内容卡片 |
| 丰收金 | `#D5A84B` | 品质标识、少量重点信息 |
| 果实橙红 | `#DF6B4F` | 优惠、紧急状态；禁止大面积使用 |
| 深棕灰 | `#2D3A31` | 正文，替代纯黑 |
| 柔和灰绿 | `#748078` | 次要信息 |

全局样式提供页面背景、文字层级、卡片、圆角按钮、胶囊标签和安全区间距等基础类。页面可复用这些类，但自动化测试不得依赖样式类名。

### 2.2 Logo 资产

以用户提供的“春华秋实”Logo 为唯一品牌源，不重绘核心苹果、叶片和中文字形。本阶段产出：

- 完整透明 Logo：用于首页品牌区。
- 简化图形标：用于小尺寸头像、空状态和后续 tabBar 图标。
- 原始 Logo 归档：保留来源，禁止反复有损转码。

图片采用小程序本地静态资源，首页首屏不依赖远程 Logo 请求。透明处理必须检查白边、裁切、小尺寸清晰度和真机显示效果。

## 3. 轻量模块化与模板替换

本阶段采用“稳定业务壳 + 标准化视图模型 + 可组合页面模块 + 模板配置 + 主题样式”的分层方式。目标是让常规换肤、模块排序和文案调整不触碰接口请求与业务处理，同时避免首期建设后台模板编辑器或通用低代码引擎。

### 3.1 稳定业务壳

`pages/index/index.js` 只负责页面生命周期、并行加载、错误状态、重试和导航事件，不包含某一套模板专属的颜色、文案或布局判断。接口原始数据先经过首页视图模型适配器，形成稳定字段，例如 `priceYuan`、`stockLabel`、`progressText` 和目标页面参数；模板模块不得直接处理整数分、接口基址或后端字段差异。

### 3.2 可组合页面模块

首页首期拆为以下独立展示模块：

- `brand-hero`：Logo、副标题、口号与服务承诺。
- `category-grid`：分类入口。
- `product-showcase`：今日甄选的加载、列表、空状态与重试。
- `group-buy-showcase`：邻里团购的加载、列表、空状态与重试。
- `quick-actions`：全部商品、今日开团、我的订单。

模块只接收序列化后的展示数据和轻量变体参数，通过统一自定义事件输出 `navigate` 或 `retry` 意图；真正的跳转和请求由页面业务壳处理。模块内部保留稳定 `data-testid`，不得把选择器定义成模板配置项。

### 3.3 模板配置与主题

默认模板键固定为 `chunhuaqiushi`。模板配置只允许控制：

- 模块顺序、显隐和轻量展示变体。
- 品牌文案、服务承诺和首页区块标题。
- 页面根主题类与模块外观变体。

模板不得配置 API 地址、订单状态规则、金额计算、支付/退款字段或任意脚本。主题样式由共享设计变量和模板级 WXSS 组成；业务组件不得散落硬编码品牌色。

后续同类模板沿用现有模块时，只需新增模板配置与主题样式，并在模板注册表登记一个键。若新模板确实需要新的展示模块，只新增模块并扩展注册表，仍复用同一视图模型、页面事件和测试契约。首期不实现后台模板管理、在线下载模板、运行时拖拽、用户自由切换或远程脚本。

### 3.4 兼容性约束

- 当前模板键集中在一个本地配置入口，切换模板不改 API 层、导航函数和自动化用例。
- 同一业务入口在不同模板下保持相同 `data-testid` 和目标页面语义。
- 模板配置读取失败或出现未知模块时回退到 `chunhuaqiushi`，未知模块跳过并记录可诊断日志，首页固定业务入口仍可用。
- 模块协议和视图模型通过静态契约验证；首期只交付并验收 `chunhuaqiushi` 一套模板，不为假设中的复杂模板提前建设能力。

## 4. 首页结构

首页保留现有三个业务入口的行为，同时升级为以下信息结构：

1. 品牌主视觉：完整 Logo、副标题、口号、自然田园浅色背景。
2. 服务承诺：有机甄选、当日到家、邻里服务三个轻量标签。
3. 快捷分类：蔬菜、水果、禽蛋、粮油、副食；点击统一进入商品列表，并携带可选关键词，不新增后端分类接口。
4. 今日甄选：调用现有 `GET /api/products`，最多展示四个在售商品，使用真实 `cover_image`、商品名、元格式价格和库存状态。
5. 邻里团购：调用现有 `GET /api/group-buys`，最多展示两个团购，显示商品、社区、人数进度和元格式团购价。
6. 快捷业务入口：全部商品、今日开团、我的订单；行为与旧首页一致。

本阶段不添加自定义 tabBar。底部导航会牵涉所有主页面结构和切换语义，留到首页、商品、购物车、订单、个人中心统一换肤阶段处理。

## 5. 数据流与容错

首页 `onLoad` 只初始化页面；`onShow` 刷新商品和团购摘要，使用户从下级页面返回时可看到更新状态。

- 商品请求复用 `apps/miniapp/utils/api.js` 的 `request` 与 `formatYuan`，禁止直接拼接 API 基址。
- 团购请求也迁移到同一请求封装，首页不得新增第二套 HTTP 处理逻辑。
- 两个摘要请求相互独立：一方失败时另一方仍可展示，品牌区和三个主业务入口始终可用。
- 首次加载显示轻量骨架或加载提示；空列表显示符合品牌语气的空状态。
- 请求失败显示页面内重试入口，同时保留简短 toast；禁止因接口错误白屏。
- 首页只读取现有接口返回字段，不修改订单、支付、退款和奖励规则。

## 6. 自动点击薄框架

### 6.1 稳定业务标识

交互与关键展示节点使用 `data-testid`，标识代表业务语义，不代表颜色、位置或文案：

| 标识 | 业务含义 |
|---|---|
| `home-brand` | 品牌主视觉已渲染 |
| `home-products-entry` | 全部商品入口 |
| `home-group-buys-entry` | 今日开团入口 |
| `home-orders-entry` | 我的订单入口 |
| `home-category-<key>` | 分类入口 |
| `home-product-<id>` | 首页商品卡 |
| `home-group-buy-<id>` | 首页团购卡 |
| `home-products-retry` | 商品摘要重试 |
| `home-group-buys-retry` | 团购摘要重试 |

自动化不得选择第几个按钮、样式类、颜色或完整可变文案。

### 6.2 测试底座

使用 `miniprogram-automator` 连接已登录且开启服务端口的微信开发者工具。第一阶段只提供：

- 环境探针：校验 macOS、开发者工具 CLI、小程序项目路径和服务端口连接。
- 统一启动/连接/关闭生命周期。
- 失败证据：当前页面路径、页面数据摘要、控制台错误、截图和异常堆栈。
- 日志输出：`/tmp/chunhuaqiushi-miniapp-e2e-<timestamp>.log`。
- 一条首页冒烟流程：启动首页，确认品牌区存在，依次点击商品、团购、订单入口并验证目标页面路径。

Mac 本地命令负责真实页面点击；Linux CI 只运行静态契约、语法、类型和现有接口门禁。待自托管 Mac Runner 建立后，再把真实页面点击接入 GitHub Actions。

### 6.3 静态契约门禁

新增可在 Docker/Linux 环境运行的首页契约验证脚本，至少检查：

- 品牌名、副标题和口号精确存在。
- 三个固定业务入口及其 `data-testid` 唯一存在。
- 商品和团购请求使用统一 API 封装。
- 金额通过整数分格式化，WXML 不直接执行 `/ 100`。
- 首页没有 `wx.login`、`wx.requestPayment`、定位或奖励敏感字段。
- `app.json` 导航标题和色彩符合品牌规范。

该门禁先红后绿；页面实现完成后必须同时通过静态契约和现有 L22 订单/售后门禁。

## 7. 第一阶段验收标准

- 小程序导航标题显示“春华秋实”，首页显示“社区甄选”和完整口号。
- 页面在 375px 等效宽度下无横向滚动，长商品名不会撑破卡片。
- 商品与团购接口任一失败时，首页主导航仍可点击。
- 首页三个固定入口可以通过 `data-testid` 自动点击并到达正确页面。
- 自动点击失败会生成日志和截图，不只返回退出码。
- Logo 透明底、无明显白边，并在常见微信设备尺寸上清晰。
- 默认模板通过单一模板键加载；切换模板配置不修改 API、导航处理和自动化选择器。
- 首页模块只消费标准化视图模型，并通过统一事件请求导航或重试。
- 新静态契约、JS 语法检查和现有 L22 静态门禁通过。
- 不修改后端业务规则、数据库、支付、退款和奖励逻辑。
