# L57 真实生产部署与灰度验收设计

## 目标

L57 将已经通过公共门禁的购买、拼团、微信支付/退款、履约、售后和会员代码部署到真实生产环境，并用可审计证据完成小流量灰度验收。本阶段不新增远期业务功能。

## 已批准边界

- 生产区域固定为腾讯云上海 `ap-shanghai`。
- 首发为单台 Ubuntu 22.04/24.04、4 核 8 GB、100 GB SSD、10 Mbps。
- 继续使用单体 API、单 Worker/API 调度实例、PostgreSQL 16、Caddy 和 Docker Compose。
- 不引入 Kubernetes、微服务、MQ、Elasticsearch；Redis 不作为 L57 前置条件。
- 域名、ICP备案、小程序备案和 HTTPS 是放量前置条件。
- 所有运行配置继续由 `.env.production`、`@community-selection/config` 和只读 `secrets/` 统一管理，不在脚本或工作流散落地址和凭据。
- 真实微信登录、JSAPI 小额支付、通知重放、退款、开团、参团、成团、失败退款、自提核销和后台会话必须验收。
- `FIRST_LAUNCH_MODE=true`；会员、优惠券、现金奖励和提现入口在首轮灰度继续关闭。
- 本地 Community Runner（标签 `[self-hosted, community]`）只验证发布候选，不绑定 `community-w01`，也不直接覆盖生产；生产部署必须保留上一已验收镜像和明确回滚路径。

## 方案

复用 L52 已验证的生产 Compose、不可变镜像、一次性迁移、加密备份和应用回滚。L57 只增加四个执行层能力：

1. **发布候选和主机就绪检查**：验证当前 Git SHA、`IMAGE_TAG` 和 Ubuntu 版本；通过腾讯云实例元数据独立绑定区域、实例 ID、实例规格和公网 IP，再用 CVM 角色执行只读 `DescribeInstances` 实时核对运行状态、CPU、内存、系统盘和购买公网带宽，并要求生产域名 A 记录集合精确相等，失败时禁止部署。
2. **隔离恢复演练**：在独立 Compose project、网络和临时 PostgreSQL volume 中恢复生产加密备份，验证迁移和核心表可读后清理演练资源；绝不连接或清理生产数据库卷。
3. **脱敏验收证据**：用版本化模板记录 P/G/R/F/A/O/B 场景，只允许订单号后四位、时间、执行人代号、结果和与场景编号绑定的截图引用；所有可控字符串扫描 openid、session token、证书、私钥、项目订单/商户单号、UUID、长 token、JSON 和完整通知报文，真实文件与截图目录由 Git 忽略；CLI 还验证截图存在、非软链，且 PNG chunk、CRC 与解压后的像素流完整。
4. **灰度门禁**：只有主机预检、生产 smoke、备份恢复、真实微信验收和连续三天资金/库存对账全部通过，才允许从内部账号扩大到一个微信群；任一资金状态不确定立即停止放量。

## 数据流与故障处理

部署始终以稳定分支固定 SHA 为 `IMAGE_TAG`。已有数据库卷时先加密备份，再停止公网流量和 API 写入，执行 `prisma migrate deploy`，启动单 API 与 Caddy，最后执行公网 smoke。迁移失败保持流量关闭并保留日志；应用异常只回退到上一已验收镜像，不逆向迁移。恢复仅通过显式确认的隔离演练命令执行，生产恢复仍需要单独人工确认。

## 验收阶段

1. **内部预检**：两个真实微信测试账号、0.01–0.10 元测试商品、一个社区和一个自提点。
2. **核心真实交易**：普通购买、拼团、退款和自提逐项留证；同时验证会员能力保持关闭，不改变普通商品价格。
3. **小流量灰度**：仅一个微信群、少量商品、严格每日库存；每日核对订单、支付、退款、库存和告警。
4. **会员灰度**：核心链路连续 3 天稳定后，才进入独立 `membership_gray` 验收，覆盖会员购买、老会员激活、赠品领取和退款拦截；通过前不对普通用户开放。
5. **扩大条件**：连续 3 天无资金差异、重复扣减、漏退款或开放告警后才扩大商品和用户范围。

## 完成标准

- L57 分支基于 `stable/l50-a3-4-business-base@ac5c7cc`，没有远期功能变更。
- 生产候选的 L50/L51/L52/L53/L56 与 L57 门禁在同一 SHA 上全部通过。
- 腾讯云上海生产主机、DNS、HTTPS、备案和微信生产参数通过预检。
- 上线前加密备份已在独立演练库恢复成功。
- 核心真实微信验收表全部通过；会员灰度在开启会员能力前单独通过，所有证据脱敏且可追溯到固定 `IMAGE_TAG`。
- 首轮灰度连续 3 天对账无差异；上一已验收镜像可执行应用回滚。
