# L26 团购成团规则与参团链路校验

## 本阶段目标

L26 明确团购成团依据，避免把访问页面、分享入口、创建待支付订单或发起支付初始化误算为成团进度。

## 成团依据

- 当前阶段 `target_count` 表示“目标成团份数”，对应现有数据模型中的 `min_quantity`。
- 只有支付成功且仍有效的团购订单计入成团进度。
- 成团进度按 `paid_quantity = sum(order.quantity)` 计算。
- 当团购未过期、状态仍为 `pending`，且 `paid_quantity >= target_count` 时，团购状态推进为 `success`。
- 普通订单不计入团购成团。
- 已关闭或已退款订单不计入团购成团。

## 不计入成团的行为

- 点击团购链接不算成团。
- 进入团购详情页不算成团。
- 点击参团购买不算成团。
- 创建待支付订单不算成团。
- 发起 mock payment 但未成功不算成团。

## 过期规则

团购截止时间到达后，本阶段不再把团购推进为 `success`。过期未达成目标的失败处理、人工退款流程和更完整的状态流转留到后续阶段。

## 本阶段不做事项

- 不做自动退款。
- 不新增奖励结算逻辑。
- 不新增真实微信支付。
- 不新增数据库表或字段。
- 不新增后端购物车接口。
- 不新增多级关系、团队玩法或代理玩法。

## 小程序文案边界

允许展示“分享团购”“邀请好友参团”“满 N 份成团”“还差 N 份成团”等成团进度文案。用户可见奖励文案如后续出现，只能使用“开团服务奖励”。

## 合规边界

成团仅由真实有效的支付成功订单份数决定，不按页面访问、分享次数、创建订单数或支付发起次数计数；本阶段不扩大开团服务奖励范围。

## 后续建议
