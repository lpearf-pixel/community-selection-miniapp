# L25 订单确认页体验与库存/数量前置校验

## 本阶段目标

L25 在 L24 小程序本地购物车基础上，增强订单确认页的下单前体验与前端防错能力，覆盖数量选择、库存提示、金额展示、自提点/社区提示和提交状态提示。

## 数量选择体验

- 订单确认页显示当前购买数量。
- 支持点击 `+` 增加数量。
- 支持点击 `-` 减少数量。
- 支持输入数量。
- 数量最小为 1。
- 商品存在有效库存时，数量不超过库存。
- 非法输入会自动修正为 1。
- 超过库存时自动修正为最大可购数量，并提示“已调整为最大可购数量”。

## 库存提示与限制

- 有库存时展示“库存：xx”。
- 库存小于等于 0 时展示“库存不足”。
- 商品没有库存字段时展示“库存以门店确认为准”。
- 库存不足时禁用或阻止提交，并提示“商品库存不足”。
- 商品列表和商品详情对库存不足商品阻止立即购买。
- 库存不足商品不会加入本地购物车。

## 金额展示

- 展示商品单价。
- 展示购买数量。
- 展示商品小计。
- 展示应付金额。
- 金额仍按整数分计算，页面展示时格式化为元。

## from_cart 兼容

- 保留 `from_cart=1` 与 `quantity` 查询参数兼容。
- 下单和 mock 支付成功后才删除购物车商品。
- 下单失败不删除购物车商品。

## 自提点/社区提示

- 展示当前社区，未选择时提示“请选择社区”。
- 展示当前自提点，未选择时提示“请选择自提点”。
- 普通购买不因缺少社区阻塞。
- 提交前仍要求存在自提点。

## 提交中防重复提交

- 请求中显示“提交中...”。
- 请求中禁止重复提交。
- 缺少自提点、库存不足等错误会明确提示。
- 接口错误 message 会继续显示在页面 error 区域。

## 后端与数据边界

- 不新增后端接口。
- 不新增数据库表。
- 不新增数据库字段。
- 不修改 Prisma schema。
- 不接真实微信支付，仍使用 mock 支付接口。
- 不新增后端购物车接口。

## 营销与合规边界

- 普通购买链路不展示奖励文案。
- 不新增营销玩法。
- 不新增跨层级关系。
- 不暴露成本价、奖励配置或库存扣减配置到本地购物车。

- 后端 `order_items` 另做阶段。
