# L19 用户端商品详情与下单入口

## 本阶段目标

L19 在 L17.5 普通购买订单能力和 L18 用户订单中心基础上，补齐用户端商品浏览与下单入口。用户可以浏览在售商品、查看商品详情、查看当前可参与开团，并通过已有订单接口完成普通购买或开团购买；创建订单并完成 mock 支付后，可在用户订单中心查看订单详情。

## 商品列表 API

- `GET /api/products`
- Query 支持 `category_id`、`keyword`、`page`、`page_size`、`only_group_enabled`、`only_in_stock`。
- 仅返回 `status = active` 的商品。
- `only_in_stock=true` 时仅返回 `stock > 0` 的商品。
- 返回商品基础展示字段、库存展示、是否支持开团、是否存在可参与开团、可参与开团数量和最低开团价。
- 不返回成本价。
- 不返回内部奖励配置。

## 商品详情 API

- `GET /api/products/:id`
- 仅允许查看 `active` 商品。
- 返回商品分类、图片、描述、价格、规格、库存、可参与开团列表，以及 `can_normal_buy` / `can_join_group_buy`。
- 可参与开团仅包含 `pending` / `success` 且未截止的开团。
- 不返回成本价。
- 不返回内部奖励配置。

## 商品可参与开团 API

- `GET /api/products/:id/group-buys`
- Query 支持 `community_id`、`page`、`page_size`。
- 仅返回当前商品下 `pending` / `success` 且 `end_time > now` 的开团。
- 传入 `community_id` 时仅返回该社区开团。

## 普通购买入口

- 继续复用 `POST /api/orders/normal`。
- 本阶段不新增统一 purchase API，避免绕过 L17.5 已有订单校验。
- 普通购买使用现有库存校验、订单创建和 mock 支付链路。
- 普通订单不产生开团服务奖励。

## 开团购买入口

- 继续复用 `POST /api/orders`。
- 商品详情和可参与开团 API 仅负责展示可参与开团，不替代订单接口的最终校验。
- 开团购买仍走现有团购订单创建、库存校验、开团校验和 mock 支付链路。

## 下单后订单中心衔接

- 创建普通订单或开团订单后，调用 `POST /api/payments/mock` 完成 mock 支付。
- 支付后通过 `GET /api/me/orders/:id` 查看用户订单详情。
- 用户订单详情仍需要 `x-user-id` 或 `x-openid`，且仅允许订单所属用户访问。

## 合规边界

- 不暴露成本价。
- 不暴露内部奖励配置。
- 不新增多级关系、团队类收益或代理类收益能力。
- 不新增购物券、用户等级权益或传播裂 变玩法。
- 不接真实微信支付。
- 不自动退款。
- 不自动打款。
- 不自动报税。
- 开团服务奖励仍只来自开团人本人发起团购下的真实有效商品成交。

## 验收方式

运行 L19 本地验收脚本：

```bash
pnpm exec tsx scripts/verify-l19-product-purchase-entry-local.ts
```

脚本覆盖：

1. 基础分类、商品、社区、自提点、用户和开团数据创建。
2. 商品列表仅展示在售商品，并隐藏成本价和内部奖励配置。
3. 商品详情展示可参与开团，并隐藏成本价和内部奖励配置。
4. 商品可参与开团列表按状态、截止时间和社区过滤。
5. 普通购买创建订单、mock 支付、订单中心查询，且不产生开团服务奖励。
6. 开团购买创建订单、mock 支付、订单中心查询。
7. 商品 API 可公开访问，用户订单详情必须带身份且禁止越权访问。
8. 复用统一合规扫描。
