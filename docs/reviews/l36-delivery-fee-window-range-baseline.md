# L36 门店配送费 / 配送时段 / 配送范围规则基线

## 本阶段目标

在 L35 履约方式选择基础上，为门店配送提供静态 baseline：配送费、配送时段、配送范围说明、订单确认页展示、后端强校验、Admin 只读查看。

## 配送费规则

第一版使用静态规则：基础配送费为 0 分，免配送门槛为空。金额仍使用整数分。

## 配送时段规则

小程序订单确认页展示今日下午、今日晚上、明日上午三个可选时段；门店配送下单必须传入合法时段编码。L36 不持久化配送时段，订单详情展示“以门店确认时段为准”。

## 配送范围说明

当前仅展示“门店周边 3-5km，具体以门店确认为准”。

## 为什么不计算距离

L36 是门店配送 baseline，不引入距离计算，避免对地址精度、定位授权、路线服务产生依赖。

## 为什么不请求定位

本阶段只需要用户手动填写收货地址，不请求用户定位，也不保存定位轨迹。

## 为什么不接地图 SDK

小程序确认页仅展示文字规则，不做路线规划，也不嵌入地图 SDK。

## 为什么不接达<!-- split -->达真实 API

本阶段不创建外部配送单，Admin 仅展示“接口未启用”的只读状态。

## 小程序订单确认页变化

选择门店配送时展示配送说明、配送范围、配送费、免配送门槛和配送时段，并校验配送时段、姓名、手机号、收货地址、发货点。

## Admin 配送规则展示

配送预留页面顶部新增配送规则卡片，显示静态 baseline、配送费、配送范围、配送时段和接口未启用提示；不提供编辑或保存入口。

## 后端安全字段边界

订单响应只返回 receiver_phone_masked 和必要的配送展示字段，不展示成本、奖励或库存扣减内部字段。

## 不改 DB

L36 不新增表、不新增字段、不新增 migration。配送规则静态写在 service 中。

## 后续 L37 建议

可继续做配送费配置持久化、配送时段配置、自提点配送范围配置。
