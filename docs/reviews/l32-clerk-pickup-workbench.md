# L32 店员自提核销工作台复盘

## 本阶段目标

L32 基于轻量后台访问控制，为门店店员提供只处理自提事项的 Admin 工作台。页面和接口聚焦待自提订单、自提码查询、自提概览、核销自提，不扩大后台管理范围。

## 店员自提工作台功能

- 顶部展示今日待自提、已核销、已完成、总件数。
- 支持按日期、自提点 ID、自提码或订单号查询。
- 自提码 `PICK-xxxxxx` 可快速定位单个订单。
- 待自提列表展示订单号、自提码、商品、数量、收货人、脱敏手机号、状态和核销按钮。
- 核销前需要二次确认，成功后刷新列表和概览。

## 后端接口清单

- `GET /api/admin/pickup/orders`
- `GET /api/admin/pickup/orders/by-code/:code`
- `POST /api/admin/pickup/orders/:id/verify`
- `GET /api/admin/pickup/summary`

## 权限边界

所有自提工作台接口都使用 `pickup.verify`。前端权限只做体验提示，后端 `requireAdminPermission("pickup.verify")` 才是安全边界。

## 信息展示边界

店员处理自提时只需要核对商品、数量、收货人、自提点和自提码，因此页面不展示金额、退款、财务、奖励、成本相关字段，降低误触和信息泄露风险。

手机号只展示 `receiver_phone_masked`，后端通过安全 mapper 输出，不直接返回完整手机号。

## 核销规则

- 未支付订单不可核销。
- 已核销或已完成订单重复请求保持幂等，不重复改写业务状态。
- 请求携带自提码时必须和订单自提码匹配。
- 核销只更新履约状态并记录业务事件，不触发支付、退款或结算动作。

## 数据库范围

本阶段不改 DB，不新增表，不新增字段，不新增 migration。

## 不是完整 RBAC

L32 只使用既有轻量权限点，不做完整 RBAC，不做账号管理，不做角色管理页面。

## 后续建议

L33 可以在不改变 L32 安全边界的前提下增加数据范围能力，例如店员只看绑定自提点订单；L32 暂不做数据范围表。
