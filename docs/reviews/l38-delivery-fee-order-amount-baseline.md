# L38 配送费计入订单金额 / 退款对账基线

## 本阶段目标

L38 在 L37 配送规则配置化基础上，把门店配送费真正写入订单金额体系，并让用户订单、后台配送、财务对账和退款上限都能看到一致的金额口径。

## 金额语义

- `product_amount_cents`：商品金额，不含配送费。
- `delivery_fee_cents`：配送费，到店自提固定为 0，门店配送按规则计算。
- `pay_amount_cents`：用户应付金额。L38 后门店配送为商品金额加配送费；到店自提等于商品金额。
- `total_amount_cents`：沿用既有商品总价语义，历史订单兼容时 `product_amount_cents` 回填为该值。

## 履约差异

到店自提不产生配送费，也不保存配送时段。门店配送会保存 `delivery_time_window_code` 与 `delivery_time_window_text`，便于订单详情和配送后台展示。

## mock 支付与退款对账

mock 支付继续只使用订单 `pay_amount_cents`，因此门店配送订单支付金额包含配送费。售后申请仍由用户填写退款金额，后台人工审核；系统只把可退上限维持为 `pay_amount_cents`，不自动决定配送费是否退。

## 财务对账

财务概览增加商品金额、配送费、应付金额和退款金额汇总；订单明细和 CSV 增加 `product_amount_cents`、`delivery_fee_cents`、`pay_amount_cents`、`refund_amount_cents`，并保留 CSV 防公式注入。

## 开团服务奖励边界

配送费不参与开团服务奖励，奖励基数继续基于真实商品成交金额；L38 不新增奖励规则，也不改变一级服务奖励流程。

## 外部能力边界

本阶段仍保持 mock 支付与人工退款记录，不接真实支付或退款通道；配送仍是门店配送/人工处理，不接真实配送平台 API，不接地图 SDK，不请求用户定位。

## L39 建议

后续可在 L39 增加配送费退款策略、部分退款明细规则、财务导出列说明和更细的退款对账报表。
