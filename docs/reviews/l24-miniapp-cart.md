# L24 小程序本地购物车 Review

## 本阶段目标

L24 在 L23 MVP 基线之上补齐小程序用户端本地购物车能力，让用户可以从商品列表或商品详情保存普通购买商品，并从购物车页选择单个商品进入订单确认页。

## 范围说明

- 本阶段只做小程序本地 Storage 购物车。
- Storage key: `cart_items`。
- 不新增数据库表。
- 不新增数据库字段。
- 不新增后端购物车接口。
- 不改真实支付能力，继续使用 mock 支付链路。

## 页面与入口

- 商品列表增加加入购物车入口，并保留直接下单。
- 商品详情增加加入购物车与去购物车入口，并保留立即购买。
- 新增购物车页，支持展示商品图、名称、规格/单位、单价、数量、小计、选择状态。
- 我的页面增加我的购物车入口，可展示本地购物车商品数量。

## 购物车页能力

- 支持增加数量、减少数量、输入数量。
- 支持选择/取消选择商品。
- 支持删除单个商品。
- 支持清空购物车。
- 底部展示已选数量与合计金额。

## 结算限制

第一版仅支持单商品结算。未选择商品时提示用户选择商品；选择多个商品时提示当前版本先选择一个商品结算。结算跳转到订单确认页，并携带 `from_cart=1` 与 `quantity`。

## 订单确认页兼容

订单确认页读取 `from_cart` 与 `quantity`，仍然调用现有商品详情接口加载商品，仍然通过普通购买接口创建订单，并继续走 mock 支付。下单与 mock 支付成功后才删除购物车中对应商品；失败时不删除。

## 合规边界

- 不接真实微信支付。
- 不新增营销扩展玩法。
- 不新增自动退款。
- 不新增自动打款。
- 不新增自动报税。
- 普通购买链路不展示奖励文案。
- 购物车不保存成本价、奖励配置、库存扣减配置或完整手机号。

## 后续建议

如后续需要多商品合并订单，应单独设计后端订单明细模型与库存、售后、退款、履约规则，不在 L24 范围内实现。
