# 购买与拼团生产验收

本清单只能在真实服务器、域名、微信生产配置和小额测试商品准备完成后执行。每项记录时间、订单号后四位、执行人、结果和脱敏截图；不得记录 openid、私钥、session token 或完整通知报文。

| 编号 | 场景 | 操作 | 必须观察到的结果 |
|---|---|---|---|
| P01 | 微信登录 | 新用户授权进入小程序 | 服务端会话签发；客户端不持有 `session_key`；测试身份 Header 无效 |
| P02 | 普通购买 | 选择自提并提交 0.01–0.10 元测试商品 | 订单金额以整数分保存；库存预占一次；拉起 JSAPI 支付 |
| P03 | 支付通知 | 完成 P02 支付 | 签名验证成功；通知回执 applied；订单只入账一次 |
| P04 | 通知重放 | 对同一支付通知做平台允许的重试观察 | 返回成功但不重复入账、扣库存或写奖励 |
| G01 | 发起拼团 | 开团人创建小额拼团并支付 | 团状态进行中；开团服务奖励尚未可提现 |
| G02 | 参团 | 第二个真实微信用户参团并支付 | 订单归属正确；人数/数量按已支付订单计算 |
| G03 | 成团 | 达到最低数量 | 团成功；未支付订单关闭；已支付订单不退款 |
| G04 | 支付不确定 | 验收环境模拟查询失败或 USERPAYING | 本轮不结团、不关单、不漏退款；产生可审查告警 |
| G05 | 拼团失败 | 创建无法成团的小额团并等待/人工触发到期 | 团失败；全部已支付订单进入退款；无开团服务奖励 |
| R01 | 退款通知 | 完成 G05 或一笔人工退款 | 退款状态成功；重复通知不重复记账；金额不超过可退余额 |
| F01 | 自提 | 店员核销已支付自提订单 | 只有授权 Admin session 可操作；订单完成；时间线和审计日志存在 |
| A01 | 后台登录 | 管理员密码 + TOTP 登录 | Secure/HttpOnly session cookie；伪造 `x-admin-*` Header 无法越权 |
| A02 | 告警中心 | 查看支付查询失败、退款异常或任务告警 | 告警可打开、解决/忽略，并记录管理员审计 |
| O01 | 单实例任务 | 连续观察两轮对账/到期扫描 | 只有一个 API 容器；advisory lock 无重复业务事件 |
| B01 | 加密备份 | 执行 `pnpm prod:backup` | 只产生 `.dump.gpg`；无 `.dump` 明文或 `.partial` |
| B02 | 恢复演练 | 在独立演练库恢复 B01 | schema/migration 一致；抽查订单、支付、退款、团购记录数量 |
| O02 | 应用回滚 | 切换到上一个验收 `IMAGE_TAG` 后再切回 | 不运行逆向迁移；两个方向公网 smoke 均通过 |

## 放量顺序

1. 内部管理员与两个测试微信账号完成全部表格。
2. 仅向一个微信群开放，限制测试商品和每日库存。
3. 首日人工盯支付通知、退款、拼团到期和 `OpsAlertLog`。
4. 连续 3 天无资金差异后再扩大群和商品。

任一资金状态不确定、退款集合不完整、库存重复扣减、通知被错误吞掉或恢复演练失败，都必须停止放量并保留现场证据。
