# 01 业务规则

## 交易闭环

用户从微信群、门店二维码或分享链接进入小程序，选择商品或团购，完成微信支付，门店根据自提时间分拣，用户自提或配送。订单完成后进入售后期，售后期结束后才结算开团服务奖励。

## 商品规则

商品必须包含：

- 名称
- 分类
- 封面图
- 详情图
- 规格
- 单位
- 售价
- 成本价
- 库存
- 是否支持开团
- 开团服务奖励类型
- 开团服务奖励值
- 上下架状态

金额统一用整数分存储。

## 团购规则

团购必须包含：

- 商品
- 开团人
- 社区
- 成团人数
- 成团件数
- 开始时间
- 截止时间
- 自提时间
- 当前人数
- 当前件数
- 状态

团购状态：

```text
pending      待成团
success      已成团
failed       成团失败
cancelled    平台取消
preparing    备货中
ready        待自提/待配送
fulfilled    已履约
closed       已关闭
```

## 成团规则

达到任一条件即可成团，具体由后台配置：

- 达到最低人数
- 达到最低件数

成团判断只统计已支付订单。

## 开团失败规则

以下情况视为开团失败：

1. 截止时间到仍未达到成团条件
2. 供应商无法供货
3. 商品质量不达标，平台主动取消
4. 成团前退款导致有效订单不足

处理方式：

- 已支付订单进入退款流程
- 未支付订单关闭
- 开团人不产生奖励
- 后台记录 AuditLog

## 订单规则

订单状态：

```text
unpaid       待支付
paid         已支付
grouped      已成团
preparing    备货中
ready        待自提/待配送
picked       已自提
delivered    已配送
completed    已完成
refunding    退款中
refunded     已退款
closed       已关闭
```

订单创建和库存扣减必须使用数据库事务。

必须支持 `client_request_id`，避免重复提交订单。

## 退款规则

退款状态：

```text
none
pending
approved
processing
success
failed
rejected
```

退款规则：

1. 未支付订单不能退款。
2. 已全额退款订单不能重复退款。
3. 支持部分退款。
4. 总退款金额不能超过订单实付金额。
5. 全额退款后订单状态为 refunded。
6. 部分退款后订单保持当前履约状态，但记录 refund_amount。
7. 退款成功后同步扣减开团服务奖励。
8. 未成团失败自动创建退款记录。
9. MOCK 模式支持模拟退款成功。

## 开团服务奖励规则

奖励只允许一级。

允许：

- 开团人本人发起团购
- 用户通过该团下单并支付
- 订单真实完成
- 售后期结束
- 奖励变为可提现

禁止：

- 二级返佣
- 三级返佣
- 团队收益
- 下级收益
- 发展人员奖励
- 入门费
- 加盟费
- 买礼包获得开团资格

奖励计算：

```text
fixed:   成交件数 * commission_value
percent: 实际成交商品金额 * commission_value / 100
none:    0
```

实际成交商品金额 = 商品实付金额 - 退款金额。

## 奖励状态

```text
estimated    预计奖励
frozen       冻结中
pending      待结算
available    可提现
withdrawn    已提现
deducted     已扣减
cancelled    已取消
```

状态流转：

1. 支付成功后生成 estimated。
2. 订单完成后变 pending。
3. completed_at + 7 天后变 available。
4. 退款成功后扣减或取消。
5. 开团失败后取消。
6. 异常订单可由后台冻结。

## 提现规则

第一版只做人工提现审核。

- 用户提交提现申请
- 后台审核
- 后台人工打款
- 后台标记已支付

不做自动打款，降低风控和复杂度。
